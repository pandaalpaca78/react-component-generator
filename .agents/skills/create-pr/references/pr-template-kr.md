# 한국어 PR 작성 및 생성

## 변경 범위 확인

- 적용되는 `AGENTS.md`와 저장소의 PR 템플릿·기여 지침을 확인한다. 저장소 템플릿의 구조를 우선하고 아래 형식은 템플릿이 없을 때 사용한다.
- 저장소, 현재 브랜치, 원격 저장소, 작업 트리 상태를 확인한다. base는 사용자 지정, 기존 PR, 저장소 기본 브랜치 순으로 판단하고 `main`으로 단정하지 않는다. 대상 원격이 모호하면 생성 전에 확인한다.
- base와 head의 merge-base를 기준으로 전체 커밋과 diff를 읽는다. 마지막 커밋만으로 PR을 요약하지 않는다. 미커밋 변경은 PR에 포함되지 않으므로 구분해 보고하고 임의로 커밋하지 않는다.
- 해당 head와 base의 기존 PR이 있으면 링크와 상태를 확인해 중복 생성을 피한다. 사용자가 수정을 요청한 경우에만 기존 PR을 수정한다.

## 제목과 본문

제목은 변경의 목적이나 사용자에게 나타나는 결과를 한국어로 간결하게 쓴다. 저장소의 제목 규칙이 있으면 따른다. 코드 식별자와 명령어는 원문을 유지한다.

본문은 최종 diff를 기준으로 처음 보는 리뷰어가 이해할 수 있게 작성한다. 문제와 변경 후 동작을 먼저 설명하고, 필요한 경우 구체적인 전후 예를 든다. 작업 대화나 폐기한 접근은 판단에 필요한 경우에만 포함한다.

```markdown
## 변경 내용

<해결한 문제와 변경 후 동작. 변경 규모에 맞게 간결하게 작성>

## 검증

- <실제로 실행한 명령과 결과>
- <미실행 검증과 이유가 있으면 명시>
```

관련 이슈, 호환성 영향, 위험, 스크린샷 등은 실제로 관련되고 근거가 있을 때만 추가한다. 이슈를 자동 종료하는 키워드는 연결이 확인되고 종료가 의도된 경우에만 사용한다. 검사 결과를 추정하거나 미실행 검사를 통과로 쓰지 않는다. 작은 변경에는 불필요한 섹션을 늘리지 않는다.

## 실행 범위

- 제목·본문 작성만 요청받으면 작성한 내용을 반환하고 원격 변경은 하지 않는다. 실제 PR 생성 요청은 생성 권한으로 간주하며 별도 형식적 승인을 추가하지 않는다.
- 사용 가능한 GitHub 연결 도구를 우선 사용하고, 필요한 기능이 없으면 인증된 `gh`를 사용한다. 생성 전에 최종 대상 저장소·base·head와 게시할 내용을 확인한다.
- PR 생성에 필요한 현재 브랜치의 일반 push는 요청 범위에 포함한다. 원격과 대상 브랜치가 명확할 때만 실행한다. 강제 push, 이력 재작성, 임의 커밋, 병합, 리뷰어 지정은 별도 요청 없이 하지 않는다.
- draft 요청이면 draft로 생성한다. 준비 상태나 사용자의 지정과 관계없이 draft 여부를 임의로 고정하지 않는다.
- CLI에서 여러 줄 본문은 임시 UTF-8 파일로 작성해 `gh pr create --body-file`에 전달한다. 제목·본문의 특수문자를 셸 코드로 해석시키지 않는다.
- 생성 요청의 결과가 불명확하면 해당 head의 PR을 조회한 후 재시도 여부를 판단한다. 인증·권한 오류가 나면 반복 생성하지 말고 원인과 준비된 제목·본문을 알린다.
- 생성 후 URL·제목·base·head·draft 여부를 확인해 보고한다. 검증 결과와 미커밋 변경 등 PR에 포함되지 않은 범위도 필요한 만큼 알린다.
